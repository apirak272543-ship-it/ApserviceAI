ผู้ให้บริการ AI (รองรับหลายค่าย + สำรองอัตโนมัติ)

เว็บแบบ Static ไม่สามารถซ่อน API Key ได้ หากเผยแพร่บน GitHub Pages ควรใช้ API Proxy ฝั่งเซิร์ฟเวอร์ และไม่ควรบันทึก Secret Key ลงในไฟล์นี้ — เพิ่มผู้ให้บริการได้หลายอันดับ เรียงจากบนลงล่าง อันดับ 1 (บนสุด) จะถูกใช้ก่อนเสมอ ถ้าอันดับ 1 เรียกไม่สำเร็จ (error/timeout) ระบบจะข้ามไปลองอันดับถัดไปให้อัตโนมัติทันที ไล่ไปเรื่อยๆ จนกว่าจะสำเร็จหรือหมดรายการ เลือกค่ายแล้วใส่แค่ API Key/Token ของตัวเองก็พอ ไม่ต้องจำ URL

AI สำรองในเครื่อง (Local AI — ไม่ผ่าน API เลย)

โหลดโมเดล AI ขนาดเล็กมารันในเบราว์เซอร์ผู้ใช้เองล้วนๆ (ผ่าน WebGPU) ใช้เมื่อผู้ให้บริการ API ทุกอันดับด้านบนใช้ไม่ได้แล้ว (token/quota หมดหมดทุกเจ้า) จะได้ตอบต่อได้แม้ไม่มี API เลย — ความฉลาดจะน้อยกว่าโมเดลใหญ่มาก เหมาะกับงานสนทนาเบาๆ ไม่ใช่งานซับซ้อน ต้องเบราว์เซอร์รองรับ WebGPU (Chrome/Edge รุ่นใหม่) และดาวน์โหลดโมเดลครั้งแรกประมาณ 600MB–900MB (แคชไว้ในเครื่อง โหลดครั้งเดียว)
เปิดใช้ AI สำรองในเครื่อง
ทำงานอัตโนมัติเฉพาะตอน API ทุกเจ้าล่มพร้อมกัน
ใช้สำหรับ Proxy หรือผู้ให้บริการที่ต้องการ Header เพิ่มเติม ห้ามใส่ข้อมูลลับหากเป็นอุปกรณ์สาธารณะ

Social Connections

เชื่อมต่อเฉพาะบัญชีที่คุณเป็นเจ้าของหรือมีสิทธิ์จัดการเท่านั้น ใส่แค่ Token ของแต่ละแพลตฟอร์มที่นี่ก็พอ ไม่ต้องตั้งค่า Meta App หรือ Server ใดๆ เพิ่ม — URL/Endpoint เตรียมไว้ให้หมดแล้ว ระบบจะเก็บ Draft ให้ตรวจ Preview ก่อนทุกครั้ง และต้องกดยืนยันอีกครั้งก่อนเผยแพร่จริง

Facebook Page

รับ Page Access Token (แบบ Never Expire) ได้จาก Graph API Explorer โดยเลือก Page ที่ต้องการ แล้วคัดลอก Access Token มาวางที่นี่

TikTok

ต้องเป็น Token ที่ขอสิทธิ์ (scope) video.publish จาก TikTok Developer Portal ของคุณเอง — การโพสต์ผ่าน URL วิดีโอโดยตรง (PULL_FROM_URL) อาจต้องยืนยันโดเมนกับ TikTok ก่อนใช้งานจริงกับบัญชีที่ไม่ใช่ Sandbox

ขั้นสูง (ไม่บังคับ) — OAuth ผ่าน Supabase

ใช้เฉพาะกรณีต้องการให้ผู้ใช้หลายคนเชื่อมต่อบัญชีตัวเองผ่านหน้าล็อกอินจริง (ต้อง deploy Supabase Edge Function เอง) — ถ้าแค่ใช้คนเดียวและมี Token อยู่แล้ว ข้ามส่วนนี้ไปได้เลย ใช้ช่องด้านบนพอ
ใช้ anon/publishable key เท่านั้น ห้ามใช้ service_role key
Facebook Page (ผ่าน OAuth)
ต้องใช้ Meta App และสิทธิ์จัดการ Page
TikTok (ผ่าน OAuth)
ต้องเปิด Content Posting API และขอสิทธิ์ video.publish

เก็บข้อมูล/เอกสารไว้ในเครื่องนี้ให้ AI ดึงมาใช้ตอบแทนการเดา ไม่แสดงในหน้าแชท ระบบจะเลือกเนื้อหาที่เกี่ยวข้องกับคำถามมาแนบให้ AI อัตโนมัติ

สำรอง/กู้คืนประวัติแชตทั้งหมด

เครื่องมือค้นเว็บ (Web Search / Web Fetch)

ใช้งานได้ทันทีโดยไม่ต้องตั้งค่าอะไรเลย (ผ่านบริการฟรี Jina AI Reader) — จำกัดประมาณ 20 ครั้ง/นาทีต่อเครื่อง ถ้าใช้บ่อยจนติด limit ใส่ Jina API Key ฟรีเพิ่มได้ (ขอได้ที่ jina.ai) จะได้โควตาสูงขึ้นเป็น 200 ครั้ง/นาที — โค้ด Python/JavaScript รันในเครื่องผู้ใช้เองผ่าน Pyodide/Sandbox ไม่ต้องตั้งค่าเช่นกัน

GitHub (Direct API — ทำงานทันที)

เชื่อมต่อ GitHub API ตรงจากเบราว์เซอร์เลย ไม่ผ่าน Supabase, ฐานข้อมูลงาน, คิวงาน หรือ Agent ตัวกลางใดๆ ต้องใช้ Personal Access Token เท่านั้น — ถ้าจะให้ AI สลับไปมาระหว่างหลายรีโพเองได้ (เช่นตอบเรื่องรีโพ A แล้วค่อยแก้รีโพ B) ให้ใช้ Classic token สิทธิ์ "repo" หรือ Fine-grained token ที่ให้สิทธิ์ครบทุกรีโพที่ต้องการ ถ้าจะจำกัดสิทธิ์แค่รีโพเดียวก็ทำได้เช่นกัน แต่ AI จะใช้ได้เฉพาะรีโพนั้น — Token จะถูกเก็บไว้ในเครื่องนี้เท่านั้น (localStorage ของเบราว์เซอร์) อย่าแชร์สกรีนช็อตหรือไฟล์ export ที่มี Token ติดไปด้วย
กรอกแค่ Token แล้วเซฟก็พอ ไม่ต้องระบุ Owner/Repo ล่วงหน้า — แค่คุยในแชตตามปกติ เช่น "ดูรีโพ apservice-admin-app ให้หน่อยว่าทำอะไร" หรือ "ช่วยอ่านไฟล์ index.html แล้วแก้บั๊ก X" AI จะเรียก github_list_repositories/github_select_repository เพื่อหารีโพที่ตรงชื่อให้เองก่อน แล้วค่อยอ่าน/แก้ไฟล์/ดู commit และ commit ให้ทันที โดยไม่ใช้คิวหรือ Runner ภายนอก
